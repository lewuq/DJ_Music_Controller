# Python 打碟上位机原型

配合 `dj_controller_firmware` 使用：单曲加载与播放、波形和播放位置显示、五个滑杆控制音量/速度/三段均衡，以及用电机角度实验性地移动播放位置。它是对视频交互的第一版近似实现，还不是完整 DJ 软件或低延迟刮碟引擎；目前尚未完成真实硬件和音频设备联调。

## Windows 启动

安装 Python 3.10～3.12 并确保包含 Tkinter，然后在此目录运行：

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python app.py
```

选择 XIAO 对应 COM 口并点击 CONNECT DEVICE；通过 LOAD TRACK 选择 WAV、FLAC 或 OGG，按 PLAY / PAUSE 播放，点击波形可跳转。勾选 Use hardware sliders 使用实体滑杆；取消勾选后可用界面滑杆独立试用。同一 COM 口一般不能同时由串口监视器和本程序占用。MP3 是否可用取决于本机 libsndfile，当前不保证支持。

窗口较小或系统显示缩放较大时，可使用右侧和底部滚动条查看全部控件；鼠标滚轮纵向滚动，Shift + 滚轮横向滚动。五个界面推子支持鼠标拖动，也可以在选中后使用上下方向键微调。

| ADC 输入 | 功能 |
|---|---|
| 模块 1 A1 | 音量 |
| 模块 1 A2 | 速度 0.5～1.5 倍（音高也会变化） |
| 模块 1 A3 | 低频均衡 |
| 模块 2 A0 | 中频均衡 |
| 模块 2 A1 | 高频均衡 |

均衡器使用 250 Hz / 4 kHz 一阶分频，每段调整范围 -12～+6 dB，约 2/3 位置对应 0 dB；它是基础音效，不等同于商用调音台。默认按 0～3.3 V 映射滑杆，实际使用时可在 `app.py` 的 `self.calibration` 中填入每路实测最小/最大电压，单位微伏。非线性或对数电位器需要实测曲线，单独校准两端不能将其变成线性。ADC 未启用或读取失败时，界面保留上次值。

电机反馈是可选的。配套的新版 STM32C5 固件使用 SimpleFOC 协议，默认 CAN 速率为 500 kbit/s、ID 为 `M`。先点击 **ENABLE FEEDBACK**，确认 ONLINE 和实际转速显示，再点击 **START** 请求进入速度闭环。默认目标为 +1.0 rad/s（约 9.55 rpm），滑块可调到 -10.0～+10.0 rad/s；正负代表目标方向。上位机每约 30 ms 发送一次 `SPEED <整数>`，整数单位为 mrad/s，例如 `SPEED 1000` 表示 1 rad/s。点击 **STOP** 停止，重新启动仍需点击 START。反馈转速是电机测量值；ARMED 是 STM32C5 控制状态，不是电机对执行成功的确认。首次联调应空载、从低速开始并准备独立断开电机电源。

启动会关闭 jog，避免正常旋转被解释为播放位置跳转；自动旋转期间不能开启 jog。在未启动速度闭环时勾选 jog，可手动转动电机，用角度变化移动播放位置；当前是基于周期反馈的粗略定位，没有唱盘触摸检测，也不是真正的变速刮碟。音频 PLAY/PAUSE 与电机 START/STOP 目前独立。电机自身固件上电可能已使能，CAN 断线时停止命令可能无法送达；连接电机前请阅读固件中的协议与安全说明。此上位机的速度控制需要配套新版 STM32C5 固件，不能直接搭配旧版 `VQ` 固件或 F103 二进制协议固件使用。

## 为什么先用 Python，如何继续

Python 是语言，Qt 是界面框架，二者可以组合：后续可使用 Python + PySide6。第一版用 Tkinter 减少安装和界面复杂度；Qt 更适合扩展漂亮的波形、设备设置和复杂布局。音频回调、串口和界面已分离，但 Python 加通用操作系统不能保证专业打碟所需的低延迟。

后续可增加可视化校准、双音轨和交叉推子、Cue、保持音高的变速、唱盘触摸检测、力反馈手感及端到端延迟测量。转成独立设备时需要音频编解码器、DMA 缓冲、DSP、存储和足够的处理能力。

`protocol.py` 解析串口数据，`serial_link.py` 管理串口，`audio_engine.py` 负责音频，`app.py` 负责界面。安装依赖后可执行 `python -m unittest discover -s tests -v` 验证核心逻辑。
