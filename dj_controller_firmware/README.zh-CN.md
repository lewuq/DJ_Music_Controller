# XIAO 打碟控制器固件

基于 Zephyr / PlatformIO。默认 `MOTOR_AUTORUN_ENABLED=1`，上电等待 1.5 秒并收到电机 CAN 反馈后，尝试发送零目标、`C1`、`E1` 和持续的 4 rad/s 速度目标。`MOTOR_AUTORUN_USB_DIAGNOSTICS=1` 保留滑杆采集和 USB 遥测。电机 SimpleFOC ID 为 M、CAN 为 500 kbit/s、反馈帧 ID 为 `0x24D`。反馈超时或发送出错会停止自动启动，复位后才重试；发送成功不代表命令被电机执行，需实机确认。

电机使用速度闭环，实际速度和手感取决于电机板的速度环参数及负载。手动干预仍可能产生阻力。首次空载测试并准备独立断电；CAN 断开时停止命令未必送达，电机板自身也可能上电默认使能。若只需手动输入可将 `MOTOR_AUTORUN_ENABLED` 设为 `0`。

CAN 命令默认不附加换行：`C1` 默认发送 `43 31 00 00 00 00 00 00`。若核对电机 CAN 固件后确认需要 LF，可设 `MOTOR_SIMPLEFOC_CAN_APPEND_LF=1`，此时 `C1` 发送 `43 31 0A 00 00 00 00 00`。两种格式是否被电机接收和执行仍需实机验证，不能只凭 CAN ACK 判断。

## 电机参数

在 `include/config.h` 中，`MOTOR_SIMPLEFOC_VELOCITY_MODE=1` 选择速度闭环，改为 `3` 可选择速度开环（电机说明书提示开环模式不能长时间运行）；`MOTOR_AUTORUN_SPEED_MRAD_S=4000` 设置 4 rad/s（正负号决定方向）；`MOTOR_AUTORUN_START_DELAY_MS=1500` 设置上电等待时间，单位毫秒；`MOTOR_AUTORUN_FEEDBACK_WAIT_MS=10000` 设置额外等待反馈时间。程序仍需收到反馈才启动，因此实际启动可能晚于 1.5 秒。修改固件宏后需要重新编译并烧录 XIAO。上位机可选择启用电机反馈控制音频，滑杆仍控制倍率；该选择不改变固件电机控制方式。固件的 10 rad/s 速度上限与目标速度是两个独立参数。

## 接线

* I²C1：D4/PB7 为 SDA，D5/PB6 为 SCL；XIAO、ADC 和滑杆共地。模块 1 地址 `0x49`，模块 2 地址 `0x48`。确认现有上拉电阻和逻辑电压。
* 使用 XIAO **背面的 CAN_H/CAN_L 焊盘**分别接电机 CAN_H/CAN_L，按需连接信号地。PB5/PB13/PB14 已由板级设备树配置，不要将逻辑 TX/RX 直接接差分总线。电机使用独立的合适电源；所附说明书建议 9 V、最高 12 V，注意正负极。
* 总线两端各需一个 120 Ω 终端。XIAO 的终端可配置，电机说明书称其板上已有终端。断电后，两个 120 Ω 并联时 CAN_H/CAN_L 之间通常约 60 Ω；先确认实物再添加电阻。

## 配置与编译

在 `include/config.h` 中设置各通道宏，`1` 启用、`0` 关闭；当前保留原工程接线：模块 1 的 A1/A2/A3，模块 2 的 A0/A1。采集周期目标为 50 ms，转换和串口输出可能增加延迟。

根据实际反馈，当前电机使用说明书中的 SimpleFOC 固件，因此默认选择 `MOTOR_PROTOCOL_SIMPLEFOC`、电机 ID `M`；使用前仍需核对实际 ID。默认自动模式会尝试解锁并发送速度。如果更换固件，需重新确认实际协议并修改 `MOTOR_PROTOCOL`，使用 F103 参考协议时必须先关闭 `MOTOR_AUTORUN_ENABLED`：

| 选择 | 波特率 | 命令与反馈 |
|---|---:|---|
| `MOTOR_PROTOCOL_DISABLED` | — | 不初始化 CAN，也不发送电机命令。 |
| `MOTOR_PROTOCOL_F103_SOURCE` | 1 Mbit/s（根据提供的 F103 时钟和时序推算） | ID 1～8；分组 8 字节有符号 q 轴电压，单位 mV、小端；`0x100+ID` 反馈角度 mrad 和转速 0.1 rpm。 |
| `MOTOR_PROTOCOL_SIMPLEFOC` | 500 kbit/s | 说明书中的字母 ID（默认 `M`）；ASCII 命令，`0x200+ID` 反馈 float32 速度与角度。电机端必须开启对应监控反馈。 |

所附说明书和 F103 参考源码描述的是**两套不同协议**，不能根据电机型号推断实际使用哪套。F103 分组协议每次会发送四路槽位，未选的三个槽位置零：如果同组有其他正在工作的电机，它们也会收到零命令。

SimpleFOC 模式下的经典 CAN 波特率由 `MOTOR_SIMPLEFOC_CAN_BITRATE` 指定，默认 500000 bit/s；`MOTOR_SIMPLEFOC_ID` 默认 `'M'`（标准帧 ID `0x04D`）。

在本目录执行 `pio run`，再使用开发板正常的 UF2 或 PlatformIO 方式烧录。`zephyr/app.overlay` 留空：当前板级设备树已配置 I²C1、CAN2、收发器待机脚和 USB CDC。

## USB 数据和电机控制

USB 以约 20 Hz 输出一行 JSON：

```json
{"v":1,"t":1234,"adc_uv":[null,1600000,1000000,2000000,2500000,900000,null,null],"motor":{"online":false,"armed":false,"angle_mrad":0,"rpm10":0,"error":0}}
```

数组顺序是模块 1 的 A0～A3、模块 2 的 A0～A3，单位为微伏。`null` 表示通道未启用或读取失败，不能当作 0 V。`online` 表示最近收到匹配的电机反馈。当前 USB 是**自定义串口设备**，并非 USB MIDI/HID，需配套上位机。

### 直接发送 SimpleFOC 命令

选择 SimpleFOC 模式，关闭自动运行或启用 USB 诊断后，可以在 USB 串口以 LF 或 CRLF 结尾发送带电机 ID 的完整命令。固件把首字符 `M` 作为 CAN 标准帧 ID，剩余字符作为 ASCII 数据；USB 的换行不直接转发，CAN 换行由独立宏决定：

| USB 输入 | CAN 标准帧 ID | 数据内容（ASCII） |
|---|---|---|
| `MC1` | `0x04D` | `C1`：选择速度模式 |
| `ME1` | `0x04D` | `E1`：使能电机 |
| `M1.0` | `0x04D` | `1.0`：设置目标，单位由电机当前模式决定 |
| `MVP0.2` | `0x04D` | `VP0.2`：设置速度 PID 比例参数 |
| `MMG7` | `0x04D` | `MG7`：请求监控 |
| `ME0` | `0x04D` | `E0`：关闭电机 |

默认数据帧长度为 8 字节，命令后面填零；如实机要求 DLC 等于实际数据长度，可把 `MOTOR_SIMPLEFOC_CAN_PAD_TO_8` 改为 `0` 后重新编译。去掉 ID 后的数据连同可选 LF 最多 8 字节，超长命令会拒绝，不会截断或自动分帧。全局 `?`、`@` 等没有电机 ID 的串口命令，以及需要超过 8 字节的命令，目前未实现转换。

每条直接命令返回 `{"v":1,"type":"can_result","id":77,"error":0}` 格式的 JSON；`error=0` 表示 CAN 发送成功且总线上有节点应答，**不代表电机已执行命令**。这只是命令发送通道，不是完整的 SimpleFOCStudio UART 透明桥接：现有程序只解析电机的速度/角度反馈帧，并不能将任意参数查询转换成 Studio 期望的串口文本回复。

直接命令不会启动本固件的 `ARM`/`SPEED` 心跳保护或速度限幅，目标、模式和使能状态由所发送命令及电机固件决定；用户应发送 `ME0` 或 `STOP` 停止，并准备独立断电方式。为防止两种控制方式相互覆盖，`ARM` 后会拒绝直接命令，但始终允许 `ME0`；发送 `STOP` 或 `ME0` 解除该状态后可再次使用直接命令。CAN 断线时停止命令可能无法送达。

输入命令以换行结束。两种协议都支持 `ARM` 和 `STOP`，但目标命令不同：

* **SimpleFOC：**`MONITOR` 发送 `MG7` 开启监控；`ARM` 依次发送零目标、配置的速度模式（默认 `C1` 为闭环）和 `E1`，初始目标仍为零。`SPEED <整数>` 设置速度，单位是毫弧度/秒，范围 -10000～10000；例如 `SPEED 1000` 对应 1 rad/s。此命令必须每 300 ms 内重复发送一次，固件每约 50 ms 转发一次速度。`STOP` 尝试发送零目标和 `E0`。
* **F103 参考源码：**`ARM` 后使用 `VQ <整数>` 设置 q 轴电压，单位 mV，默认限制 ±300 mV，命令同样需要持续重复发送。该协议不是速度闭环。

只有 CAN 初始化成功且有近期反馈才允许 ARM。300 ms 没收到对应的目标命令、反馈过期或发送失败时，固件尝试置零并解除解锁。参考 F103 固件本身在 500 ms 无 CAN 命令时会将目标置零。这些是软件保护，CAN 断线时停止命令可能无法送达，仍需要可靠的电源断开方式。控制器未解锁并不代表电机自身的功率输出已关闭：说明书称其上电可能默认使能。

CAN 发送发生错误或超时时，控制器尝试停止 CAN 外设并锁定故障，需要复位才能再次启动；若停止外设失败，不能保证已排队帧被取消。采集、看门狗和串口目前在同一线程运行，ADC 或总线阻塞会延后超时检查，300 ms 并非硬实时的安全停机保证。`MG7`、帧填充和停止行为必须以实机验证为准。

代码分层为 `adc_inputs.c`、`motor.c` 和提供串口协议与调度的 `main.c`。先让电机空载，确认反馈、方向、限值和停止行为，再安装转盘。

## 向独立嵌入式设备迁移

目前由电脑负责解码音乐、音效和波形。独立运行需要增加存储、DAC 或 I²S 音频编解码器与功放、DMA 音频缓冲、实时 DSP 任务、显示和交互界面。可以保留统一的滑杆与电机接口，将音频引擎逐步移植为 C/C++，先测延迟、CPU 和内存再决定音频格式及效果。真实刮碟还需要低延迟变速播放及触摸/手动控制状态，仅有电机角度无法判断手是否按住转盘。
