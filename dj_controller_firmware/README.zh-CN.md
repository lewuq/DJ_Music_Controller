# XIAO 打碟控制器固件

基于 Zephyr / PlatformIO，采集两块 ADS1115 并通过 USB CDC 向 `dj_audio_controller` 发送 JSON 数据，同时提供可选的 CAN 电机协议。当前属于原型，尚未完成真实电机和整机联调。

## 接线

* I²C1：D4/PB7 为 SDA，D5/PB6 为 SCL；XIAO、ADC 和滑杆共地。模块 1 地址 `0x49`，模块 2 地址 `0x48`。确认现有上拉电阻和逻辑电压。
* 使用 XIAO **背面的 CAN_H/CAN_L 焊盘**分别接电机 CAN_H/CAN_L，按需连接信号地。PB5/PB13/PB14 已由板级设备树配置，不要将逻辑 TX/RX 直接接差分总线。电机使用独立的合适电源；所附说明书建议 9 V、最高 12 V，注意正负极。
* 总线两端各需一个 120 Ω 终端。XIAO 的终端可配置，电机说明书称其板上已有终端。断电后，两个 120 Ω 并联时 CAN_H/CAN_L 之间通常约 60 Ω；先确认实物再添加电阻。

## 配置与编译

在 `include/config.h` 中设置各通道宏，`1` 启用、`0` 关闭；当前保留原工程接线：模块 1 的 A1/A2/A3，模块 2 的 A0/A1。采集周期目标为 50 ms，转换和串口输出可能增加延迟。

根据实际反馈，当前电机使用说明书中的 SimpleFOC 固件，因此默认选择 `MOTOR_PROTOCOL_SIMPLEFOC`、电机 ID `M`；使用前仍需核对实际 ID。控制器不会在未主动解锁时发送非零目标。如果更换固件，需重新确认实际协议并修改 `MOTOR_PROTOCOL`：

| 选择 | 波特率 | 命令与反馈 |
|---|---:|---|
| `MOTOR_PROTOCOL_DISABLED` | — | 不初始化 CAN，也不发送电机命令。 |
| `MOTOR_PROTOCOL_F103_SOURCE` | 1 Mbit/s（根据提供的 F103 时钟和时序推算） | ID 1～8；分组 8 字节有符号 q 轴电压，单位 mV、小端；`0x100+ID` 反馈角度 mrad 和转速 0.1 rpm。 |
| `MOTOR_PROTOCOL_SIMPLEFOC` | 500 kbit/s | 说明书中的字母 ID（默认 `M`）；ASCII 命令，`0x200+ID` 反馈 float32 速度与角度。电机端必须开启对应监控反馈。 |

所附说明书和 F103 参考源码描述的是**两套不同协议**，不能根据电机型号推断实际使用哪套。F103 分组协议每次会发送四路槽位，未选的三个槽位置零：如果同组有其他正在工作的电机，它们也会收到零命令。

在本目录执行 `pio run`，再使用开发板正常的 UF2 或 PlatformIO 方式烧录。`zephyr/app.overlay` 留空：当前板级设备树已配置 I²C1、CAN2、收发器待机脚和 USB CDC。

## USB 数据和电机控制

USB 以约 20 Hz 输出一行 JSON：

```json
{"v":1,"t":1234,"adc_uv":[null,1600000,1000000,2000000,2500000,900000,null,null],"motor":{"online":false,"armed":false,"angle_mrad":0,"rpm10":0,"error":0}}
```

数组顺序是模块 1 的 A0～A3、模块 2 的 A0～A3，单位为微伏。`null` 表示通道未启用或读取失败，不能当作 0 V。`online` 表示最近收到匹配的电机反馈。当前 USB 是**自定义串口设备**，并非 USB MIDI/HID，需配套上位机。

输入命令以换行结束。两种协议都支持 `ARM` 和 `STOP`，但目标命令不同：

* **SimpleFOC：**`MONITOR` 发送 `MG7` 开启监控；`ARM` 依次发送零目标、`C1`（速度闭环）和 `E1`，初始目标仍为零。`SPEED <整数>` 设置速度，单位是毫弧度/秒，范围 -10000～10000；例如 `SPEED 1000` 对应 1 rad/s。此命令必须每 300 ms 内重复发送一次，固件每约 50 ms 转发一次速度。`STOP` 尝试发送零目标和 `E0`。
* **F103 参考源码：**`ARM` 后使用 `VQ <整数>` 设置 q 轴电压，单位 mV，默认限制 ±300 mV，命令同样需要持续重复发送。该协议不是速度闭环。

只有 CAN 初始化成功且有近期反馈才允许 ARM。300 ms 没收到对应的目标命令、反馈过期或发送失败时，固件尝试置零并解除解锁。参考 F103 固件本身在 500 ms 无 CAN 命令时会将目标置零。这些是软件保护，CAN 断线时停止命令可能无法送达，仍需要可靠的电源断开方式。控制器未解锁并不代表电机自身的功率输出已关闭：说明书称其上电可能默认使能。

CAN 发送发生错误或超时时，控制器尝试停止 CAN 外设并锁定故障，需要复位才能再次启动；若停止外设失败，不能保证已排队帧被取消。采集、看门狗和串口目前在同一线程运行，ADC 或总线阻塞会延后超时检查，300 ms 并非硬实时的安全停机保证。`MG7`、帧填充和停止行为必须以实机验证为准。

代码分层为 `adc_inputs.c`、`motor.c` 和提供串口协议与调度的 `main.c`。先让电机空载，确认反馈、方向、限值和停止行为，再安装转盘。

## 向独立嵌入式设备迁移

目前由电脑负责解码音乐、音效和波形。独立运行需要增加存储、DAC 或 I²S 音频编解码器与功放、DMA 音频缓冲、实时 DSP 任务、显示和交互界面。可以保留统一的滑杆与电机接口，将音频引擎逐步移植为 C/C++，先测延迟、CPU 和内存再决定音频格式及效果。真实刮碟还需要低延迟变速播放及触摸/手动控制状态，仅有电机角度无法判断手是否按住转盘。
